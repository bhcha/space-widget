# AI Agents installation inventory

Open SpaceWidget Preferences → **AI Agents** → **다시 검사**. The inventory is read-only and refreshes CLI and desktop entries independently. It does not install hooks or establish an integration connection.

- Executables are found using absolute PATH directories, common native/Homebrew locations, and up to 32 recent numeric Node versions under NVM_DIR (default ~/.nvm). A valid NVM_BIN is also checked. Version probes prepend the executable directory to their sanitized PATH so an NVM-installed CLI can find its sibling Node interpreter when launched from Finder. Symlink duplicates are removed. Shell aliases/functions and per-terminal environment changes are not evaluated.
- Desktop apps are identified by bundle identifier through Launch Services and the system/user Applications folders, including renamed registered apps. App versions come from bundle metadata, not from an unrelated CLI.
- Claude Code 1.0.62 or later is required by this integration's capability check: 1.0.41 separated Stop/SubagentStop and 1.0.62 added SessionStart. This is a required-feature baseline, not a claim that earlier versions have no hooks. [Official changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).
- Codex capability is checked using `features list` for `hooks` or its deprecated alias `codex_hooks`. Missing feature evidence, prerelease/unrecognized version output, or failed probes remain unknown. No invented minimum version is used. [Official hooks reference](https://learn.chatgpt.com/docs/hooks).
- Desktop presence alone does not prove the installed build's hook capability. In particular, ordinary Claude Chat is not Claude Code. Local Code sessions share hook settings with CLI, but detecting Claude.app does not establish Code availability, account eligibility, or its embedded runtime version. The UI explicitly reports this uncertainty. [Desktop shared configuration](https://code.claude.com/docs/en/desktop#shared-configuration).

Capability is distinct from readiness: CLI checks run with temporary HOME, config directories, and cwd. They do not read project policy, establish exact-hash trust, verify hook installation, or prove callback delivery. The UI therefore says connection is unverified even for a supported runtime. No scan can mark Codex trusted/connected. Configuration paths shown are from SpaceWidget's environment (`CODEX_HOME`, `CLAUDE_CONFIG_DIR`); individual terminals and desktop sessions may override these.

Subprocesses use argument arrays, closed stdin, discarded stderr, a 3-second deadline, and a 32 KiB stdout limit. Only version and feature queries run; no shell startup files, login shell, interactive session, or installation commands run. Unknown results remain visible and rescannable. Tests use temporary executable/app fixtures and never invoke installed agents or write their settings.

Validation: run `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test`. Tests exercise capability boundaries, absent agents, version/feature failures, Claude Chat distinction, CLI/desktop version independence, custom config paths, duplicate executables, actual subprocess isolation/timeouts/output limits, and rescan state. Live desktop capability/permissions and hook connectivity are not asserted by this inventory or these fixture tests.
